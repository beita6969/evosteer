## 修复与诊断

### HumanEval：完整函数提交丢失公开辅助代码

旧评分器在发现候选包含顶层函数时删除整个公开 prompt，目的是避免把未完成
函数头接在完整实现前，但也删除了题面提供的导入、辅助函数及公开常量。
一个真实运行错误与此对应；这不是模型没有收到题面，而是执行装配丢失题面代码。

`fdbe3ea` 只替换公开目标函数 stub，保留其前面的公开 scaffold；原生函数体续写
仍沿用原拼接方式。完整模块中已有的相同公开前缀不重复拼接；公开代码不能覆盖
owner 自己的实现。带 `__future__` 的模块保持合法头部和 owner 原始代码顺序。
测试、标准实现、其他候选和模型调用都不参与装配。原始提交不改写。
全部 164 个公开 HumanEval prompt 的末尾函数均与公开入口名一致。
新 scorer 标识为 `humaneval-native-public-scaffold@2`；旧记录不改写。

同一批旧 32 份代码在同一原生沙箱／限额下只读比较：旧装配 **28/32**，
新装配 **29/32**，仅一条 verdict 变化；旧装配复评分与原保存分数全部相符。
这是 scorer 诊断，不是新模型成绩，也没有向 actor 提供诊断结果。
随后新生成的 32 题同样取得 **29/32，90.625%**；实际 33 次 owner 调用，
一次接口修复。剩余两项测试失败、一项运行错误，不能按公开 scaffold 缺失改判。

### AIME：最终通道截断与运行时消息角色

- 旧续写只接续未闭合 reasoning／空 final。若在 `length` 边界已输出部分 final，
  它会过早停止续写，甚至把多位整数的前缀当答案。
- 新增 `final-unfinished`：保留原始输出证据，在原 token 流上续写至自然停止。
  Actor、trusted broker 和持久化来源校验使用相同状态。额度／调用耗尽时，
  不把看似可解析的截断 final 提交为答案，也不从 reasoning 捞数字。
- 分块预算提示原来追加成新的 user 消息，取代数学问题成为最新 user turn。
  现在合入开头 system 指令；真实题目保持 user 角色和内容，不伪造新用户请求。
- 总输出 81,920、单块最多 32,768、尾部额度 4,096、最多八次调用不变，thinking-on。
  尾部额度仍不是强制 final 阶段；不保证解决所有不结束推理的长尾。
  旧 30 题中没有已观察到的截断非空 final，本项通过合成边界用例复现；
  不能把它描述成旧六条预算耗尽的已证实共同原因。

新轮中实际出现一次非空 final 的 `length` 截断，已按同一 token 流续写。
续写随后包含重复通道标记，系统没有从中猜答案，而是在共享预算内交由同一 owner
进行一次接口澄清后提交。该真实边界与合成回归一起验证了新路径，不代表所有长尾
都会自然结束，也不是另开独立推导后投票。
