# Skill learning repair — independent candidate

The paused Step 8 diagnostic retains its original artifacts, labels, optimizer,
posterior and library. It is not an accepted 250-step architecture-matched IID run.

## What is changed

- Shared HumanEval public-code assembly retains public helpers/imports for body
  and target-function submissions. The verifier is versioned; old rewards are
  not rewritten. Four original saved candidates were replayed with their original
  native checker: three former NameErrors disappeared under the corrected assembly.
- Terminal submission outcomes retain actual finish reason, cap, parse status and
  admission/execution facts. A length stop is not a completed reasoning claim.
  Optional per-domain action budgets are an explicit new condition, not a parser fix.
- `public-task-semantics@8` / `phase-context@5` distinguishes advisory reads,
  actual native observations and terminal state. It permits a short resource
  decision before fully solving, without adding an unscored routing step.
- `public-procedure-advice@3` supplies four new, scoped, public procedure candidates.
  It does not replace old skill IDs or inherit their posteriors. Candidates are
  **not yet qualified as useful by real-model development evidence**.
- Read reporting separates trajectories, canonical sources, repeat reads, visible
  bodies and later task actions. A broader evidence count is not certified efficacy.
  Cold-start still needs its complete diagnostic window; no AND/OR rule is changed.
- TTB decomposition, final gradient-work facts and native scoring diagnostics are
  read-only. HealthBench criterion request/response journals remain private.

## Qualify value before a new long training run

Use `development_collection` with a fixed, source-disjoint development manifest,
base snapshot, seed 0 and `skill_utility_policy` frozen before requests. It accepts
all seven native domains; AIME development names its historical population rather
than claiming AIME2026 evaluation data. The candidate library and skills-off arms
must have identical non-library controls and retain every planned source outcome.

`python -m skillev_private.experiments.skill_utility --skills-off ... --skills-on ...
--application-reviews ... --output ...` combines these complete native outcomes
with attributable reviews of real returned bodies and visible subsequent actions.
It reports all-source reward/success/cost differences. Calls or successful labels
alone cannot qualify a library. This is training-development evidence, not IID,
not a per-read causal estimate, and not an automatic new training schedule.

## Explicit supervised initialization

`SkillUseWarmup` is a separate, opt-in initialization API: only forward-adapter
supervision on original action tokens; tool bodies are conditions, not labels.
It requires source isolation, successful native outcomes, reviewed application
examples and genuine not-called or inapplicable-after-read controls. Invalid action
trajectories are not warmup demonstrations; their original TTB artifacts remain.
It saves its own corpus, named Adam state and cursor. It does not update backward
LoRA, Z, native reward, posterior or evolution, and is never called by default TTB.

Keep original Step-0, warmup initialization and warmup+TTB results separate. No
real warmup has been executed and no qualified corpus has yet been manufactured
from the old read counts. Resume/new initialization is a new declared decision;
no long training run starts merely because these component tests pass.

## Development practice and real per-replica admission

`training-development-skill-practice@2` adds explicitly fictional resource-use
teaching examples to the same owner's development context: reading a relevant
procedure before a long solution, solving directly when appropriate, abandoning
inapplicable advice, and consulting an already visible body without rereading.
The examples contain no current task answer or selected skill ID. They are not
executed history, supervised labels, invocation evidence, or a formal read quota.
Version 1 stays unchanged. Real successful, body-visible application still needs
an attributable review before admission to the separate warmup corpus.

servers allowed 32 requests each, but the collector still shared eight actor

capacity must be present in each server's measured runtime limits, both before
